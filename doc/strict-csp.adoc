= Get a strict Content Security Policy
:toc: left
:toclevels: 3

== Do I need this guide?

Gate One does **not** add a Content Security Policy unless a route
declares a `csp` block. If you only proxy a page through Gate One,
with no `csp` block and no custom injection, there is nothing to do:
the page's own policy (if any) passes through unchanged.

You need this guide if one of these is true:

* you enable `csp` on a route (`mode`: `nonce`, `hash` or `merge`);
* your application already sends its own CSP;
* you inject custom HTML, styles or scripts (`inject` bundle,
  userscripts, plugins);
* you proxy an external site that sends a CSP.

The last two cases are the subtle ones: the gateway and the origin can
both emit a policy, and **the browser enforces all of them**. A strict
origin policy can block Gate One's guard; a strict gateway policy can
block your application's inline code.

== What Gate One injects

For a frontend route with the guard active, Gate One adds:

* an inline `<script>` (the guard: session probe, login recovery, UI
  gating, user badge);
* a `<style>` element created at runtime by the guard, carrying the
  CSP nonce of the response;
* optionally PWA wiring (manifest link, service worker registration)
  and custom injections from the route bundle.

Since the guard's UI is entirely class-based, it does not set
`style="..."` attributes and does not need `'unsafe-inline'`. The one
runtime `<style>` is nonced from `document.currentScript.nonce`.

== The four modes

[options="header",cols="1,3"]
|===
| mode | behaviour

| `off` | Nothing is emitted or amended. The origin's policy (if any)
is the only one.
| `merge` | The origin policy is preserved; the gateway only appends
the hashes of its own injected scripts to `script-src-elem` /
`script-src` / `default-src`. No policy of its own.
| `hash` | Gate One emits its own policy; the guard and other injected
scripts are allow-listed by SHA-256 hashes. The body is not rewritten.
| `nonce` | Gate One emits its own policy with a per-response nonce and
stamps inline `<script>` tags. This is the recommended mode for
applications that accept a per-response nonce.
|===

`reportOnly: true` emits `Content-Security-Policy-Report-Only`: the
policy is evaluated and violations are reported, but nothing is
blocked. Use it to roll out a policy without breaking the site.

=== Nonce semantics — read this before enforcing

In `nonce` mode, Gate One stamps **every inline `<script>`** in the
HTML response (unless it already carries a nonce). This includes the
application's own inline scripts and any custom injection. As a
consequence:

* it removes the need for `'unsafe-inline'` in `script-src`;
* it does **not** protect against a `<script>` injected into the HTML
  by a server-side vulnerability, because that script is stamped too.

If you need protection against server-side HTML injection, use the
`hash` or `merge` mode with a strict origin policy, and keep
application scripts in external files.

`stampScripts`:

* absent / `inline` (default): only `<script>` tags without `src` are
  stamped; external scripts stay governed by the host allow-list;
* `all`: every `<script>` tag is stamped (only meaningful with a host
  allow-list or `'strict-dynamic'`).

== Styles: the real constraint

CSS has two different mechanisms, and only one accepts a nonce:

[options="header",cols="1,2,2"]
|===
| mechanism | controlled by | nonce?

| `<style>…</style>` | `style-src-elem` (falls back to `style-src`) | yes
| `style="…"` attribute | `style-src-attr` (falls back to `style-src`) | **no**
|===

A nonce (or hash) never applies to a `style` **attribute**. To obtain
a strict policy without `'unsafe-inline'`:

* use external CSS files (`style-src 'self'`);
* use classes instead of `element.style` / `style="..."`;
* let Gate One nonce its own runtime `<style>` (it already does);
* for third-party widgets that insist on style attributes, isolate the
  exception with `style-src-attr 'unsafe-inline'` rather than relaxing
  the whole `style-src`.

Gate One's guard follows this rule: badge, banners, chips and gating
states are classes; hidden gated elements use
`[data-gtw-gated-off]{display:none}`. A static test fails the build if
an inline style reappears in the guard.

=== Application checklist for styles

* no `style="..."` attributes (including generated by JS);
* no `element.style = ...` / `.style.cssText` / `.style.display`;
* use `classList` and classes, or an external stylesheet;
* no `<style>` without a nonce (the gateway does not stamp application
  `<style>` tags; move them to a CSS file);
* SVG `style` attributes are style attributes too;
* third-party embeds: check whether they need `style-src-attr
  'unsafe-inline'`.

== Scripts and event handlers

A strict `script-src` without `'unsafe-inline'` also blocks:

* `onclick="..."` and other inline event handlers (`script-src-attr`);
* `javascript:` URLs;
* `eval()`, `new Function()`, `setTimeout("code")` (`'unsafe-eval'`);
* `document.write` of scripts without a nonce/hash.

Use `addEventListener`, external scripts and data attributes.

With `nonce` mode, inline `<script>` tags are stamped by the gateway,
so existing inline scripts work — but see the server-side injection
caveat above. For the strictest setup, move scripts to external files
and rely on `script-src 'self'` only.

== A strict configuration

Start report-only:

[source,json]
----
"csp": {
  "mode": "nonce",
  "reportOnly": true,
  "directives": {
    "default-src": "'none'",
    "script-src": "'self'",
    "style-src": "'self'",
    "img-src": ["'self'", "data:"],
    "font-src": "'self'",
    "connect-src": ["'self'", "https://auth.cladone.com"],
    "worker-src": "'self'",
    "frame-ancestors": "'none'",
    "object-src": "'none'",
    "base-uri": "'none'",
    "form-action": "'self'"
  }
}
----

Why these directives:

[options="header",cols="1,3"]
|===
| directive | role

| `default-src 'none'` | deny by default; every resource type must be
explicitly allowed.
| `script-src 'self'` | external same-origin scripts; the gateway adds
its nonce and hashes.
| `style-src 'self'` | external same-origin styles; the gateway adds
its nonce.
| `img-src` | add `data:` only if the application uses data-URI icons.
| `font-src` | self-hosted fonts; add the font CDN if used.
| `connect-src` | `fetch`, XHR, EventSource and WebSocket endpoints.
Add the IdP origin if the application calls it directly.
| `worker-src` | the PWA service worker (`'self'`).
| `frame-ancestors 'none'` | anti-clickjacking.
| `object-src 'none'`, `base-uri 'none'` | remove plugin/base-tag
injection vectors.
| `form-action 'self'` | restrict form destinations.
|===

Keep `reportOnly: true` until the reports are clean, then switch to
`false`. A policy that emits violations is not protecting the page in
report-only mode.

== Reading violations

The gateway serves a collector (default
`/__gate-one_csp/report`) and logs one line per violation:

[source,text]
----
CSP VIOLATION host="app.example.com" directive="style-src-elem"
blocked="inline" document="https://app.example.com/" source="..." line=572
----

Typical signatures:

[options="header",cols="2,2,3"]
|===
| directive | blocked | usual cause / fix

| `style-src-elem` | `inline` | a `<style>` without nonce: move to an
external CSS file (Gate One's own guard style is nonced).
| `style-src-attr` | `inline` | `style="..."` or `element.style`: use
classes; or isolate with `style-src-attr 'unsafe-inline'`.
| `script-src-elem` / `script-src` | `inline` | an inline script; in
nonce mode the gateway stamps it, so check that the policy is not the
origin's (the origin policy can still block it).
| `script-src-attr` | `inline` | `onclick=` and friends: use
`addEventListener`.
| `connect-src` | `https://...` | missing API/SSE/WebSocket origin.
| `img-src` | `data:` / CDN | missing source.
| `frame-src` | `https://...` | embedded iframe origin.
| `worker-src` | URL | service worker origin.
|===

Browser DevTools also shows the violating element and the computed
policy; the gateway log is the aggregate view across users.

== External sites and `upstream`

For a proxified external site that already sends a CSP, the browser
enforces **both** policies: the origin's and the gateway's, whichever
is stricter. Gate One never removes or weakens the origin policy.

Consequences:

* the guard's inline script/style must be allowed by the origin policy;
  `merge` appends the script hashes to the origin's `script-src-elem`,
  but the guard's runtime `<style>` is nonced in the **gateway** policy,
  not the origin's. A strict origin `style-src` can therefore block the
  guard;
* if you control the origin, allow `'self'` (or the guard's style) in
  its `style-src`, or remove the origin CSP only for a site you fully
  trust;
* `upstream.responseHeaders.remove` can strip the origin's CSP, but do
  it consciously: you are removing the origin's protection. Prefer
  `merge` and a compatible origin policy;
* external sites that use inline styles themselves will need
  `style-src-attr 'unsafe-inline'` or a refactor you do not control.

This is the one case where "strict CSP without `'unsafe-inline'`" may
be impossible without changing the origin. Document the exception per
route.

== PWA, MCP, SSE and WebSocket

* **PWA**: `worker-src 'self'` for the service worker; `manifest-src
  'self'` if your policy declares it; the Workbox runtime is self-hosted.
* **MCP**: the MCP endpoint is same-origin (`/mcp`); `connect-src
  'self'` is enough for HTTP. If an MCP client uses a WebSocket, add its
  origin.
* **SSE** (`EventSource`) and **WebSocket** are governed by
  `connect-src`, not `script-src`.
* **IdP redirects**: login is a top-level navigation, not `connect-src`;
  `form-action` applies only to forms, not to `location.href`.

== Rollout procedure

1. Enable `reportOnly: true` with the strict directives.
2. Load the main pages; watch the browser console and the gateway
   `CSP VIOLATION` logs.
3. Fix one directive family at a time (styles first: they are the most
   common).
4. Re-run the UI smoke tests and a real navigation with a session.
5. Switch `reportOnly: false` only after a clean period.
6. Keep a rollback: `reportOnly: true` (or `mode: "off"`) can be applied
   by `SIGHUP` without a restart.

== Minimal test commands

[source,bash]
----
# the header actually emitted (nonce changes per response)
curl -sD - -o /dev/null https://app.example.com/ \
  | grep -i '^content-security-policy'

# aggregate violations
docker logs <gate-one-container> 2>&1 | grep 'CSP VIOLATION'

# route-level validation
gate-one -config api-routes.json -check
----

== Known limitations

* Gate One does not stamp application `<style>` tags; use external CSS.
* Style attributes cannot be nonced: classes or `style-src-attr
  'unsafe-inline'`.
* In `nonce` mode, all inline scripts are stamped; it is not a defense
  against server-side HTML injection. Use `hash`/`merge` plus a strict
  origin policy.
* A proxified external site's CSP is enforced in addition to the
  gateway's; an incompatible origin policy can block the guard.
* Third-party widgets may require a documented `style-src-attr` or
  `script-src` exception.

Gate One's own UI (guard, badge, banners) is strict by construction and
does not require `'unsafe-inline'`.
